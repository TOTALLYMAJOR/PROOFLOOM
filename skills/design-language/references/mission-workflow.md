# Design Mission Workflow

Use the simplest front door from the consuming repository:

```bash
design-intelligence "Improve the proposal comparison flow"
```

The result infers the surface mode, presents three product-fit directions, recommends one, records reference research status, and declares the rendered-proof gate.

Rules:

- A recommendation is not approval.
- Do not edit implementation until the user selects a direction.
- `--direction recommended` is an explicit user selection when the user runs or authorizes it.
- A supplied URL or `DESIGN.md` remains research input until its observed patterns, product relevance, original transformation, and rejected identity elements are recorded.
- `--save` is the convenience write. Without it or another explicit output option, startup remains read-only.
- Use the repository's existing browser and test hierarchy for proof.
